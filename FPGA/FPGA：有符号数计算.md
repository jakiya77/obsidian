# 有符号数计算：Two's Complement 补码笔记

>[!tldr] 
>n-bit 补码范围：-2^(n-1) ~ 2^(n-1)-1
>最高位为 0：值 = 无符号值
>最高位为 1：值 = 无符号值 - 2^n
8-bit：最高位为 1 时，值 = 无符号值 - 256
signed overflow：同号相加，结果变号
Verilog 判断：overflow = (a[7] == b[7]) && (s[7] != a[7])

## 1. 有符号数不是“去掉符号位看大小”

在数字电路里，常见的有符号数表示方式是 **二进制补码 Two's Complement**。

补码不是：

```text
最高位 = 符号位
剩下几位 = 数值大小
```

这种是“原码”的想法，不是补码。

补码里，**所有 bit 都参与数值计算**，只是最高位的权重是负的。

---

## 2. n-bit 补码的取值范围

对于 n 位补码：

```text
范围 = -2^(n-1) ~ 2^(n-1)-1
```

例如 8-bit 补码：

```text
范围 = -128 ~ +127
```

因为：

```text
-2^7 = -128
2^7 - 1 = 127
```

---

## 3. 8-bit 补码的权重

8-bit 数：

```text
b[7] b[6] b[5] b[4] b[3] b[2] b[1] b[0]
```

对应权重是：

```text
-128  +64  +32  +16  +8   +4   +2   +1
```

所以：

```text
8'h90 = 1001 0000
```

它的值是：

```text
1×(-128) + 0×64 + 0×32 + 1×16
= -128 + 16
= -112
```

因此：

```text
8'h90 = -112
```

---

## 4. 快速判断补码数值

对于 n-bit 补码：

```text
如果最高位是 0：
    signed value = unsigned value

如果最高位是 1：
    signed value = unsigned value - 2^n
```

注意是减 `2^n`，不是减 `2^(n-1)`。

因为 `2^n` 是整个 n-bit 系统的模数。

---

## 5. 8-bit 常用例子

```text
8'h00 = 0000 0000 = 0
8'h01 = 0000 0001 = 1
8'h7f = 0111 1111 = 127
8'h80 = 1000 0000 = 128 - 256 = -128
8'h90 = 1001 0000 = 144 - 256 = -112
8'hff = 1111 1111 = 255 - 256 = -1
```

---

## 6. 为什么是减 256？

因为 8-bit 一共有：

```text
2^8 = 256
```

种状态。

无符号解释：

```text
0000 0000 ~ 1111 1111
0 ~ 255
```

有符号补码解释：

```text
0000 0000 ~ 0111 1111
0 ~ 127

1000 0000 ~ 1111 1111
-128 ~ -1
```

所以当最高位是 1 时，要从无符号值绕回负数区间：

```text
signed value = unsigned value - 256
```

例如：

```text
8'h90 = 144

144 - 256 = -112
```

---

## 7. 补码加法

补码加法和无符号加法在硬件上是一样的：

```verilog
assign s = a + b;
```

硬件只做二进制加法，不区分有符号还是无符号。

区别在于：**我们如何解释结果**。

例如：

```text
8'h90 + 8'h70
```

二进制加法：

```text
  1001 0000
+ 0111 0000
------------
1 0000 0000
```

结果只保留低 8 位：

```text
s = 0000 0000 = 8'h00
```

有符号解释：

```text
8'h90 = -112
8'h70 = +112

-112 + 112 = 0
```

所以结果正确，没有 signed overflow。

---

## 8. Signed overflow 判断

有符号溢出只发生在两种情况：

```text
正数 + 正数 = 负数
负数 + 负数 = 正数
```

也就是说：

```text
a 和 b 同号
但是 sum 和 a 异号
```

Verilog 写法：

```verilog
assign overflow = (a[7] == b[7]) && (s[7] != a[7]);
```

也可以写成门级逻辑：

```verilog
assign overflow = (~a[7] & ~b[7] &  s[7]) |
                  ( a[7] &  b[7] & ~s[7]);
```

---

## 9. 为什么不能只写 `a[7] ^ s[7]`

错误写法：

```verilog
assign overflow = a[7] ^ s[7];
```

这个只判断：

```text
a 的符号和结果 s 的符号是否不同
```

但它没有看 `b` 的符号。

反例：

```text
a = 8'h90 = -112
b = 8'h70 = +112
s = 8'h00 = 0
```

这里：

```text
a[7] = 1
s[7] = 0
a[7] ^ s[7] = 1
```

但实际上：

```text
-112 + 112 = 0
```

没有溢出。

所以 signed overflow 必须判断：

```text
a 和 b 是否同号
结果 s 是否变号
```

---

## 10. 无符号 carry out 不等于 signed overflow

无符号加法关心的是：

```text
有没有超过 255
```

有符号加法关心的是：

```text
有没有超过 -128 ~ +127 的范围
```

例如：

```text
8'h90 + 8'h70 = 1_0000_0000
```

有一个 carry out，但是 signed 结果是：

```text
-112 + 112 = 0
```

所以没有 signed overflow。

结论：

```text
carry out 是 unsigned overflow 的概念
signed overflow 要看符号变化
```

---

## 11. 符号扩展 sign extension

把小位宽有符号数扩展到大位宽时，要复制最高位。

例如 4-bit 的 `1010`：

```text
4-bit: 1010
```

最高位是 1，所以扩展成 8-bit：

```text
1111 1010
```

不能补 0：

```text
0000 1010  // 这是错误的，会把负数变成正数
```

Verilog 写法：

```verilog
assign out = {{4{in[3]}}, in};
```

如果 `in[3] = 1`，前面补 1；  
如果 `in[3] = 0`，前面补 0。
