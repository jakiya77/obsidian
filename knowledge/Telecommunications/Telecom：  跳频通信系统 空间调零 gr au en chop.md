## 1. 物理过程与数据结构抽象

跳频的最简模型是收发双方按约定序列，每隔一定时隙更换一次载波频率。


**物理过程示例**：

假设系统有4个可用频点 $\mathcal{F}=\{2.10, 2.15, 2.20, 2.25\}\text{ GHz}$，每个频点驻留 $T_h=100\ \mu s$。

跳的动作即为状态的切换：从第 $k$ 跳的 $f_k=2.10\text{ GHz}$，切换到第 $k+1$ 跳的 $f_{k+1}=2.25\text{ GHz}$。

**数据结构抽象**：

整个跳频通信可视为一个数组，当状态由 $Hop[1] \rightarrow Hop[2]$ 时，随之切换的不仅是频率，还包括该频点绑定的所有阵列参数：

Plaintext

```
Hop[k]
│
├── time         当前时间窗
├── frequency    当前载频 f_k
├── data         当前发送的数据
├── channel      当前信道
├── calibration  当前频点阵列校准参数 C(f_k)
└── weight       当前频点空间权值 w(f_k)
```

## 2. 频率变化对阵列响应的影响机理

当天线间距为 $d$，信号从角度 $\theta$ 入射时，传播时延差 $\Delta\tau = \frac{d\sin\theta}{c}$ 与频率无关。但时延对应的**相位差**与频率强相关：

$$\Delta\phi = 2\pi f\frac{d\sin\theta}{c}$$

**实例**：

同一物理方向 $\theta=30^\circ$，在 $f_1=2\text{ GHz}$ 时对应相位差为 $\Delta\phi_1$。

跳频至 $f_2=3\text{ GHz}$ 时，信号方向未变，但阵元间的相位差变成了 $\Delta\phi_2 = \frac{3}{2}\Delta\phi_1$。

**结论**：阵列导向矢量是频率的函数 $\mathbf{a}(\theta,f)$，不能仅写为 $\mathbf{a}(\theta)$。

  

## 3. 全数字阵列的本质

全数字阵列的核心是**每根天线都有独立的数字通道**，具备逐阵元施加独立复数权值的能力。

**架构示例（4阵元）**：

Plaintext

```
ANT1 → RF1 → ADC1 → x1[n] ─× w1 ─┐
ANT2 → RF2 → ADC2 → x2[n] ─× w2 ─┤
ANT3 → RF3 → ADC3 → x3[n] ─× w3 ─┤→ Σ → y[n]
ANT4 → RF4 → ADC4 → x4[n] ─× w4 ─┘
```

其数字输出为：$y[n] = w_1^*x_1[n] + w_2^*x_2[n] + w_3^*x_3[n] + w_4^*x_4[n]$。

其中 $w_m = A_me^{j\phi_m}$。这使得在频率切换时，系统能灵活替换这组数字。

例如 $f_1$ 时的权值 $\mathbf{w}(f_1) = [1, e^{j20^\circ}, e^{j40^\circ}, e^{j60^\circ}]^T$，跳到 $f_2$ 时可立即替换为 $\mathbf{w}(f_2) = [1, e^{j30^\circ}, e^{j60^\circ}, e^{j90^\circ}]^T$。

## 4. 标定参数（Calibration）与波束权值（Beam Weight）

全数字阵列仅提供执行能力，它不知道具体该乘什么数值。施加的最终权值由两部分组成：

**实际权值 = 标定参数 × 波束权值**

  

$$w_{m,\text{actual}} = C_m(f) \times w_{m,\text{beam}}(f)$$

- **标定参数 $C_m(f)$**：用于纠正硬件自身的误差。真实的射频通道特性随频率变化，需通过测试生成查找表（LUT）。
    
      
    - _LUT实例_：系统在 $2.25\text{ GHz}$ 时，通道2的硬件特性为 $H_2(f_2) = 0.92e^{j14^\circ}$。系统查表后，提取补偿值 $C_2(f_2) = \frac{1}{0.92}e^{-j14^\circ}$ 进行纠正，使其趋近于理想值 $1$。
        
          
        
- **波束权值 $w_{m,\text{beam}}(f)$**：用于人为制造阵元幅相差，从而形成空间主瓣或零陷。
    
      
    

## 5. 全数字阵列与同步权值切换的区别

两者高度相关，但层级不同。

  

- **全数字阵列 = 能不能换**
    
      
    
- **同步权值切换 = 什么时候换、换哪一组（控制逻辑）**
    
      
    

**反例**：

一个具备独立数字通道的全数字阵列系统，若控制程序写为：

  

Python

```
w = [1, 1, 1, 1]
for every hop:
    continue using w
```

此时系统具备硬件能力，但未执行“同步切换”，无法适应跳频系统。

  

**计算机系统类比**：

  

- **全数字阵列** $\approx$ 电脑硬件（CPU等执行单元）
    
      
    
- **阵列标定LUT** $\approx$ 硬件驱动（告诉系统硬件误差）
    
      
    
- **波束权值** $\approx$ 运行数据/参数（算法目标）
    
      
    
- **跳频同步切换** $\approx$ 调度器（到指定时间点，切换指定参数）
    
      
    

## 6. 工程项目书撰写建议与痛点转移

**合并描述**：

避免将“全数字阵列”与“同步切换”强行并列为两大问题，可压缩为一句话：

  

> “对于具备逐通道数字加权能力的全数字阵列，可根据跳频同步信息，调用当前频点对应的阵列校准参数和自适应空间权值，实现不同跳频频点下空间响应的快速匹配。”
> 
>   

**明确核心难点**：

如果系统满足“每跳窄带 + 全数字阵列 + 标定完成 + 同步更新”，则每一跳单独看都是一个**频率已知的普通窄带阵列问题**。“高速跳频”仅作为工程适配条件。

项目书的重点应聚焦于**空间自适应调零的真实难点**：

  

1. 强压制环境下的 BLMS 算法收敛性。
    
      
    
2. 多干扰源同时调零的自由度分配。
    
      
    
3. 干扰动态变化时的实时跟踪能力。
    
      
    
4. 信号与干扰角度相近（信干近角）时的性能退化问题。
    
      
    
5. 实际阵列残余幅相误差下的零陷深度与稳定性。
